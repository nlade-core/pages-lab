repo size

At what point does GitHub actually push back on a project being too big — and how far is this whole six-part lab from any of those points? Why bother: it's the difference between "technically unlimited" and what actually happens if you push it.

Technical version

Two real thresholds tested directly, not cited from docs alone: pushing a 50-100 MiB file triggers a warning; pushing over 100 MiB gets hard-blocked by GitHub's pre-receive hook. Done in a disposable scratch repo, not this one — a rejected push still means the object briefly touched a remote, and a large file that succeeds lives in git history forever unless the history itself is rewritten, which this project won't do just to make a point. Combined with GitHub's own published soft limits for repo size, Pages site size, and bandwidth.

Tested directly

Real pushes, real GitHub responses — done in a separate, disposable repo created just for this test, meant to be removed once it's no longer needed, specifically so this bloat never touches pages-lab's own history.

Write-up

GitHub's own docs (cited, not paraphrased from memory): individual files get a warning past 50 MiB and are hard-blocked past 100 MiB — confirmed directly above, exact numbers match. Beyond single files: repos are recommended to stay under 1GB (under 5GB "strongly recommended" as a hard outer bound), a GitHub Pages source repo has the same 1GB recommended limit, and a published Pages site itself is capped at 1GB. None of that is enforced by testing here — actually reproducing a 1GB+ repo just to watch it get flagged isn't a reasonable thing to do to GitHub's infrastructure for a demo.

Two more documented limits that aren't practically testable at all without real cost: bandwidth is soft-capped at 100GB/month, and Pages builds are soft-limited to 10/hour (though that specific cap doesn't apply to a site built via a custom Actions workflow, which is worth knowing if you ever lean on that harder than this project has).

Where this project actually sits: check the number above. Six experiments, plain HTML/CSS/JS, no images or binaries — nowhere close to any of these ceilings, and that's itself the honest finding: for a project shaped like this one, the limits are effectively irrelevant. They start to matter the moment binary assets, datasets, or build artifacts enter the picture, none of which pages-lab ever needed.
