routing

Can links to "sub-pages" that don't really exist as files still work, even though GitHub Pages can't fake them on the server side?

Technical version

GitHub Pages serves files only, no server-side rewrites. Client-side routing (History API push/replaceState) works fine for in-page navigation, but a fresh load or refresh on a fake sub-path 404s because no matching file exists. This tests the standard workaround: a custom 404.html that redirects back with the intended path in sessionStorage.

Write-up

The fix works, but it's not free: watch the address bar on a fresh deep-link load and you'll see it change twice — once as the browser lands on the 404 and gets bounced to the experiment's base URL, then again as the script restores the real intended path. That flicker is the honest cost of not having a real server. It also depends on JavaScript and sessionStorage being available; with JS disabled, a deep link just shows GitHub's default 404, full stop.
