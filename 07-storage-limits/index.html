storage

If you type something into this page and reload it, does it remember? Depends entirely on where it was kept — an ordinary variable forgets, two browser storage mechanisms don't. Below: the same three-way test, live, plus your actual device's real storage quota rather than a number copied from documentation.

Technical version

Compares three places to hold a value: a plain JS variable (dies with the page, nothing to configure), localStorage (synchronous, string-only, a small per-origin cap), and IndexedDB (asynchronous, structured/binary-capable, quota tied to real device disk space rather than a fixed number). Also calls navigator.storage.estimate() for this origin's actual live usage/quota, and stores a real generated Blob in IndexedDB — something localStorage can't hold natively at all, only as bloated base64 text.

What IndexedDB can hold that localStorage can't

localStorage is text-only — a real image would have to be crammed into text as base64 (about a third bigger, and awkward past a few KB). IndexedDB stores the actual binary Blob directly. Write-up

All three "remember a note" boxes look identical while you're typing — the difference only shows up on reload, which is exactly the point: storage choice is invisible until the moment you actually need it. The "None" box is guaranteed empty after a reload; autocomplete="off" plus an explicit clear on load rules out the browser's own form-restore quietly faking a save that never happened — a real, easy-to-miss false positive if left to a plain input's default behavior.

localStorage reads back synchronously, instantly, no callback needed. IndexedDB is asynchronous even for a single tiny string — noticeably more code for the same job, which is the real cost of its extra capability, not the API being badly designed.

The quota box above is the honest version of a question that's easy to answer wrong from memory: the real number is whatever this specific browser, on this specific device, actually reports — not a fixed spec value. Expect it to look enormous (often a large fraction of free disk) rather than the ~5-10MB figure that's specifically a localStorage-only convention, not a platform-wide cap.

Neither mechanism survives everything. Clearing site data removes both. Safari in particular can evict a site's script-writable storage after about a week without a visit, as part of its anti-tracking behavior — worth knowing before treating either as permanent.
